2. Segmen churn

Setiap grup memakai filter dimensi lain, tetapi menampilkan semua level dimensinya sendiri. Batang abu-abu = n < 30 (tidak dibaca). Angka di kanan: churn rate dan jumlah pelanggan (n).

Segmen kontrak × internet × metode bayar (sesuai filter)

Label n < 100 = terlalu kecil untuk rekomendasi utama.

3. Retensi per tenure

Kurva retensi (Kaplan-Meier, pendekatan dari tenure)

Bukan kurva kohort sebenarnya: tidak ada tanggal bergabung/berhenti, dan kontrak adalah kontrak saat ini. Pelanggan kontrak tahunan hampir tidak bisa churn sebelum kontrak habis, jadi kurvanya tinggi di awal. Ujung kurva (tenure di atas ±60 bulan) berbasis sedikit pelanggan dan kurang andal.

Churn per kelompok tenure (sesuai filter)

4. Revenue & skenario

Revenue bulanan hilang (lost MRR) per segmen, seluruh data

Skenario program retensi estimated

Revenue terselamatkan per tahun = (churn lama − churn baru) × pelanggan segmen × ARPU segmen × 12. Batas biaya impas = revenue terselamatkan ÷ pelanggan segmen. Asumsi: ARPU = rata-rata MonthlyCharges, USD, penurunan churn berlaku merata di segmen; efek program belum teruji.

5. Batasan

  • Satu potret waktu, tanpa tanggal. Kurva retensi hanya pendekatan dari tenure.
  • Pola belum tentu penyebab: setelah kontrak dan tenure disamakan, selisih Electronic check, Online Security, dan Tech Support mengecil sekitar separuh (lihat laporan).
  • Segmen kecil mudah tampak ekstrem; selalu baca n dan interval kepercayaan.
  • Dataset sampel buatan IBM; polanya bisa lebih rapi daripada data perusahaan nyata.
